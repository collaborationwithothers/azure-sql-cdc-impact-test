# Verification: Azure SQL Database claims

Checked: 2026-11-22, against Microsoft Learn, by the documentation-verification
agent. Verdicts are VERIFIED, PARTIAL, REFUTED or UNVERIFIABLE. An
UNVERIFIABLE claim does not ship in code or docs until a run proves it.

Sources:
- P: https://learn.microsoft.com/azure/azure-sql/database/resource-limits-vcore-elastic-pools?view=azuresql
- S: https://learn.microsoft.com/azure/azure-sql/database/resource-limits-vcore-single-databases?view=azuresql
- CDC: https://learn.microsoft.com/azure/azure-sql/database/change-data-capture-overview?view=azuresql
- RG: https://learn.microsoft.com/azure/azure-sql/database/resource-limits-logical-server?view=azuresql#resource-governance

## Documented limits, General Purpose standard-series (Gen5) elastic pools

VERIFIED (source P). The last column is from the single-database page (S), at
the same vCore count. The pool page says limits for a database inside a pool are
generally the same as for a single database of the same compute size.

| Pool vCores | Max log rate per pool (MiB/s) | Max data IOPS per pool | Memory (GB) | Max workers per pool | Single-database log rate at same size (MiB/s) |
| --- | --- | --- | --- | --- | --- |
| 4 | 24 | 2,800 | 20.8 | 420 | 18 |
| 6 | 36 | 4,200 | 31.1 | 630 | 27 |
| 8 | 48 | 5,600 | 41.5 | 840 | 36 |
| 10 | 60 | 7,000 | 51.9 | 1,050 | 45 |
| 12 | 62.5 | 8,400 | 62.3 | 1,260 | 50 |
| 14 | 62.5 | 9,800 | 72.7 | 1,470 | 50 |
| 16 | 62.5 | 11,200 | 83 | 1,680 | 50 |

- Pool log rate is 6 MiB/s per vCore up to 10 vCores and stops at 62.5 MiB/s
  from 12 vCores. Linear extrapolation above 10 vCores is wrong.
- A 2 vCore single database has a 9 MiB/s log rate (S).

## Per-database cap inside a pool

PARTIAL (P, RG).
- Per-database max vCores also governs data IO, log IO, memory and workers,
  proportionally.
- No document gives the log rate for a pooled database capped at 2 vCores.
- Inference, not documented: about 9 MiB/s, as for a 2 vCore single database.
  That is well below the 24 MiB/s pool limit, so with two databases capped at
  2 vCores the per-database cap may bind before the pool does.
- The harness records `primary_max_log_rate` (per database) and
  `instance_max_log_rate` (the pool) from `sys.dm_user_db_resource_governance`.
  Recorded values win.

## Zone redundancy

VERIFIED (https://learn.microsoft.com/azure/reliability/reliability-sql-database,
https://learn.microsoft.com/azure/reliability/regions-list).
- General Purpose zone redundancy applies to elastic pools, on standard-series
  hardware, in every region with availability zones. Sweden Central has three.
- It can increase transaction commit time.

## CDC

- Capture every 20 seconds, cleanup hourly, frequency not customisable:
  VERIFIED (CDC).
- Default retention three days: VERIFIED (CDC).
- Changing retention with `sys.sp_cdc_change_job @retention`: UNVERIFIABLE for
  Azure SQL Database. The reference page says SQL Server only. Must be tested
  live before it is relied on.
- `sys.sp_cdc_cleanup_change_table` on demand: PARTIAL. The Azure CDC page says
  users can trigger cleanup manually and links this procedure. It takes
  `@capture_instance` and `@low_water_mark`. Tested live before relied on.
- Log cannot truncate until the capture scan catches up: VERIFIED (CDC).
- CDC supported on any vCore tier, including pools: VERIFIED (CDC). Microsoft
  advises at most as many CDC-enabled databases in a pool as the pool has
  vCores.
- Entra versus SQL creator mismatch: VERIFIED as a documented limitation (CDC,
  section "Microsoft Entra ID"). `sys.sp_cdc_enable_db` needs db_owner.
- A user-assigned managed identity that is the Entra-only server admin can
  enable CDC: UNVERIFIABLE from docs. This is spike item 2.

## DMVs

- `sys.dm_elastic_pool_resource_stats`: VERIFIED. Queryable from any user
  database in the pool. New row every few seconds, about 40 minutes kept.
  Needs VIEW SERVER STATE.
- `sys.dm_db_resource_stats`: VERIFIED. 15 second rows, about 1 hour kept.
- `sys.dm_user_db_resource_governance`: VERIFIED. Columns
  `primary_max_log_rate`, `instance_max_log_rate`, `primary_group_max_io`,
  `pool_max_io`, `primary_group_max_cpu`, worker limits. Server admin or Entra
  admin sees all databases in the pool.
- `sys.dm_db_wait_stats`: VERIFIED. Current database only, VIEW DATABASE STATE.
- `sys.dm_os_wait_stats` for pooled databases: VERIFIED. Needs server admin,
  Entra admin, or `##MS_ServerStateReader##`.
- `sys.dm_cdc_log_scan_sessions`, `sys.dm_cdc_errors`: VERIFIED for Azure SQL
  Database. Up to 32 sessions kept, reset on failover.

## Wait types

VERIFIED (RG). `LOG_RATE_GOVERNOR` is database level, `POOL_LOG_RATE_GOVERNOR`
pool level, `INSTANCE_LOG_RATE_GOVERNOR` instance level. Feedback waits
`HADR_THROTTLE_LOG_RATE_*` can lower the log rate below the documented limit.

## Logging

PARTIAL. Minimal logging is not supported in Azure SQL Database
(https://learn.microsoft.com/sql/t-sql/statements/bulk-insert-transact-sql).
Seeding is therefore fully logged and subject to the log rate limits.

## SqlClient managed identity

VERIFIED (https://learn.microsoft.com/sql/connect/ado-net/sql/azure-active-directory-authentication).
`Authentication=Active Directory Managed Identity` with `User ID` set to the
client ID of a user-assigned identity.
